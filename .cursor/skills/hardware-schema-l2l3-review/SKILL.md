# 元器件 L2/L3 分类审查

## 核心原则

> **L3 只表达稳定的结构/机制差异；材料、封装、参数等级、平台叫法，优先下沉成字段。**

**L2 / L3 职责分工：**
- **L2** 持有该大类下所有子类的**共有字段**，是选型入口；L2 名称应能覆盖其下所有 L3，不能用某个 L3 的特征来命名 L2
- **L3** 只持有**专属字段**，用于与同 L2 下其他 L3 区分；有共有字段的两个子类应放在同一 L2 下，而不是拆成两个 L2
- 判断是否需要新建 L2：若两个候选子类**几乎没有共有字段**，才考虑拆分 L2

---

## 新增 L2/L3 的探索流程（遇到 schema 未覆盖的新品类）

当出现一个**现有 schema 命名上没有包含**的分类（如来自得捷/立创等渠道的新类目），**禁止仅凭名称拍脑袋新增节点或字段**。必须先探索清楚该分类的真实特点，再决定层级归属和字段。

### 第 0 步：先弄清"它到底是什么"

1. **抽样真实数据**：找该分类下的样本（数据集、CSV、渠道详情页），看实际在售产品的属性、参数、描述，而不是只看类目名称。
   - 反例教训：得捷"触摸开关"从名称看像电容感应开关，抽样数据后发现实际是**机械轻触按钮**（有操作力/行程/SPST-NO 触点），归属完全不同。
2. **识别工作机制与物理结构**：判断它和现有 L3 是不是同一种机制（决定能否合并），还是全新机制（可能需要新节点）。
3. **统计规模**：看 SKU 量级，判断是否值得单独建节点；极少量（如 < 几十 SKU）或纯配件（开关帽、触头块、照明模块）通常不纳入。

### 第 1 步：决定层级归属（用决策顺序，不要跳步）

按以下顺序判断，命中即停：

| 顺序 | 判断 | 处理 |
|------|------|------|
| ① | 能否归入**已有 L3**（机制相同，仅材质/封装/参数等级不同）？ | 是 → 合并进已有 L3，差异下沉为字段（见"合并判断补充规则"） |
| ② | 机制有稳定结构差异，但与**某个已有 L2 的其他 L3 共有大部分字段**？ | 是 → 在该 L2 下**新增一个 L3** |
| ③ | 与所有现有 L2 的字段集都**几乎不重叠**（共有字段过少）？ | 是 → **新增一个 L2**，并在其下建 L3 |
| ④ | 属于其他大类（如射频开关已归在射频无线大类）/纯配件/超出本品类范畴？ | 是 → **不纳入**，避免一个器件被两个 L3 命中（违反互斥原则） |

- 反例教训：射频开关在"射频无线"大类已存在，就**不应**在开关 schema 再建 `RF_Microwave_Switch_Base`，否则同一器件两处命中。
- 反例教训：霍尔效应操纵杆是**有源器件**，放进纯机械触点的 L2 会导致大量 L2 字段不适用（违反 L2-Q5），应放到同为霍尔效应有源器件的 L2 下。

### 第 2 步：生成对应字段（属性）

新增 L2/L3 后必须配齐字段。字段**不是凭空想象**，而是从真实数据和选型逻辑反推。

**(a) 字段来源 —— 从哪里来**

> **总原则：以实际选型为本，抽样数据为辅。字段集不能被抽样数据局限。**
> 抽样数据（渠道详情页/数据集）往往只列出部分规格，**很可能缺失关键选型参数**。绝不能"抽样里有什么就只做什么"。必须以"工程师选型/替代时真正需要比较的参数"为准，**抽样里缺失的关键参数要主动补齐**（依据规格书通用参数、行业标准、同类 L3 字段集补充）。

1. **选型决策反推（主来源）**：问"工程师选这个器件时会比较什么、什么参数错了会选错料、替代时哪些参数必须对齐"，这些就是核心字段——无论抽样数据里有没有出现，都要纳入。
2. **抽样数据的规格列（参考）**：渠道详情页/数据集里**高频出现、且有区分度**的规格列，作为字段的参考来源和命名/取值依据（如操纵杆数据中的"轴数""供电电压""输出"）。但抽样仅是参考下界，不是上限。
3. **对标同类 L3（补全）**：参考同 L2 下已有 L3 的字段集，机制相近的沿用同名字段（便于跨 L3 比较），并据此发现抽样中遗漏但本应具备的关键字段。

**校验**：字段草案完成后，回到选型场景自检一遍——"拿着这套字段，能不能完成一次完整选型/替代判断？"如果还缺关键参数（如缺额定值、缺关键性能指标），即使抽样数据里没有，也要补上。

**(b) 字段归属 —— 放 L2 还是 L3**

- 放 L2：该 L2 下**全体 L3 都有**的字段（过 L2-Q5）。
- 放 L3：仅该 L3 专属、用于和同 L2 其他 L3 区分的字段（至少 3 个，过 Q2）。
- 拿不准时默认放 L3；只有确认全体 L3 共有才上提到 L2。

**(c) 字段筛选 —— 每个字段都要过"两个维度"**

| 维度 | 要求 | 不满足则 |
|------|------|----------|
| 价值 | 影响选型 / 替代 / 合规决策，是工程师真正会比较的参数 | 低价值字段（如纯营销描述）不纳入 |
| 采集性 | 能从规格书/渠道数据稳定获得 | 难采集字段（如需实测、厂商不公开）不纳入 |

在字段描述里用 `[高价值/易采集]`、`[中价值/中难采集]` 等标注，延续现有 schema 习惯。

> **宁缺毋滥，不堆砌：字段不是越多越好。** 每个字段都要能回答"少了它，这次选型/替代会不会做错或做不了？"——只有答案为"是"（即**选型不可或缺**）才保留。这与 (a) 的"主动补全"并不矛盾：(a) 补的是**关键且缺失**的选型参数，(c) 砍的是**可有可无、为求全而罗列**的参数。两者共同目标是得到一套"既不漏关键、也不掺水"的精炼字段集。
>
> 典型应砍掉的"凑数字段"：与选型无关的物理尺寸细节、厂商内部编号、营销描述、几乎不影响选型决策的次要参数、和已有字段高度冗余的派生量。

**(d) 字段元数据 —— 每个字段必须填全这些列**

与现有 schema 列结构保持一致，逐列填写：

| 列 | 填写要求 |
|----|---------|
| 属性中文名 | 简洁、业界通用叫法 |
| 属性英文名 | `snake_case`；数值带单位后缀（如 `supply_voltage_v`、`max_frequency_ghz`）；布尔用 `is_`/`has_` 前缀 |
| 模块分类 | 归入 技术参数 / 合规参数 / 封装参数 / 交易参数 之一 |
| 类型 | `DOUBLE / INT / ENUM / BOOLEAN / VARCHAR` |
| 小数点精度 | 数值型给精度，非数值填 `-` |
| 基准单位 | 统一单位（V/A/mm/GHz…），无量纲填 `-` |
| 值域约束 | 数值给范围（如 `> 0`、`-100 ~ 100`）；ENUM 列全部枚举值；可空字段注明 `NULL` 条件 |
| 描述(兼作 LLM Prompt) | 含价值/采集性标注 + 该参数对选型/替代的意义；这段描述会直接作为补全模型的 prompt，须写清楚 |

**(e) 字段验收 —— 仍须过审查清单**

- 新增 L3 字段须过 L3 的 Q1~Q5 与"禁止规则"（不得以应用场景/参数等级/营销叫法命名字段或 L3）。
- 同机制仅材质不同的，不新建字段族，用 `material`/`substrate` 枚举字段区分（见"合并判断补充规则"）。

### 第 3 步：落地后回归审查

把新增节点放回完整结构，重跑"审查清单"第一步（L2）和第二步（L3），确认没有引入 L2-Q5（字段不全共有）、Q3（互斥性破坏）等新问题。

## 审查清单

### 第一步：审查 L2（先于 L3）

对每一个 L2，回答以下问题：

| # | 问题 | 若答案为"是" → 处理方式 |
|---|------|------------------------|
| L2-Q1 | L2 名称是否用了某个 L3 的特征来命名（如"LC无源"、"固态"、"模拟"）？ | 是 → 改为能覆盖所有 L3 的更宽泛名称 |
| L2-Q2 | 两个不同 L2 之间是否存在**大量共有字段**（>50% 重叠）？ | 是 → 考虑合并为一个 L2，原来的两个作为 L3 |
| L2-Q3 | 该 L2 下是否**缺乏真正的共有字段**（L3 之间几乎没有公共属性）？ | 是 → 该 L2 存在意义不足，考虑重构 |
| L2-Q5 | L2 中是否存在**并非所有 L3 都具有的字段**？（如某字段只有部分 L3 适用）| 是 → 将该字段下移到对应 L3，L2 只保留全体 L3 真正共有的字段 |
| L2-Q4 | 该 L2 是否只有**一个 L3**，且没有增加更多 L3 的可能？ | 是 → L2/L3 可能冗余，考虑合并层级 |

### 第二步：审查 L3

对每一个 L3，依次回答下面 5 个问题：

| # | 问题 | 若答案为"否" → 处理方式 |
|---|------|------------------------|
| Q1 | 该 L3 与同 L2 下其他 L3 之间是否存在**稳定的物理结构或工作机制差异**？ | 否 → 考虑合并或下沉为字段 |
| Q2 | 该 L3 是否有至少 3 个**专属的、对选型有价值**的字段（与其他 L3 不重叠）？ | 否 → 通常不值得单独做 L3 |
| Q3 | 一个实际元件是否可能**同时命中两个** L3（互斥性检验）？ | 是 → 至少有一个应改为字段 |
| Q4 | 该 L3 名称是否是**行业长期成立的结构性分类**，而非某平台/营销叫法？ | 否 → 改为字段枚举值 |
| Q5 | 如果不拆这个 L3，能否用 **1~2 个字段**完整表达？ | 是 → 优先下沉成字段，不建议保留 L3 |

## 合并判断补充规则

> **若两个候选 L3 的工作机制/功能相同，仅材质不同，应合并为一个 L3，用 `material` / `substrate` 字段区分。**

典型判断路径：
1. 工作机制是否相同？（如都是压电谐振、都是极性电解）
2. 核心选型字段是否高度重叠（>80%）？
3. 材质差异是否只影响 1~2 个参数数值（如 Q 值范围、温度系数），而不引入全新字段？

三条都"是" → 合并，材质作为字段枚举值。

**例**：`Ceramic_Filter` 与 `Crystal_Filter` 均为压电谐振，字段高度重叠，Q 值差异可用数值字段表达 → 合并为 `Piezoelectric_Resonator_Filter`，加字段 `substrate_material = Ceramic / Quartz`。

---

## 禁止规则（红线，不得以此划分 L3）

> **绝对不能以应用场景、特定用途或某个属性字段的值来划分 L3。**

| 错误示例 | 本质 | 正确做法 |
|----------|------|----------|
| 工业级 MCU / 车规电容 | 温度等级 / 认证等级 | 字段：`temp_grade = Commercial/Industrial/Military` |
| 8 位 MCU / 32 位 MCU | 参数数值 | 字段：`cpu_architecture_bit = 8/16/32/64` |
| 低功耗运放 / 大电流 LDO | 参数等级 | 字段：数值范围 |
| 低通滤波器 / 带通滤波器 | 频率响应功能描述 | 字段：`filter_type = Low_Pass/Band_Pass/...` |
| 无线 MCU / 蓝牙 SoC | 集成外设特征 | 字段/Tag：`wireless_protocol = BLE/WiFi/Zigbee` |
| 音频功放（仅因用于音频） | 应用场景 | 不应做 L3，除非架构/接口体系也明显不同 |

**判断口诀**：如果这个 L3 的名字里有"级"、"型"、"位"、"用"、"专用"、"特定"，大概率是错的。

---

## 常见"应下沉为字段"的情形

以下情形**不应做 L3**，应作为 L2 或 L3 的字段属性：

- 安装/封装方式：`SMD / THT / Radial / Axial`
- 材质变体：同一机制下只换了材料（如 PET/PP/PPS 薄膜、陶瓷/石英压电谐振体）
- 参数等级：高压 / 低功耗 / 大电流（数值字段）
- 电解质/极板材料：液态/聚合物/铌/铌氧化物（字段枚举）
- 营销/平台叫法：某厂商自定义的型号系列名
- 频率响应特征：低通/高通/带通/带阻（拓扑功能，应为 `filter_type` 字段）
- 应用场景/用途：工业、车规、音频、通信（应为 Tag 或字段）

---

## 应独立为 L3 的典型情形

下列情形通常**应保留 L3**：

- 储能/工作机制明显不同（如双电层 EDLC vs 锂离子电容）
- 失效模式与降额规则差异明显（如铝电解 vs 固体电解）
- 核心选型路径不同，字段集有明显差异（如 Audio_DSP vs General_Programmable_DSP）
- 高集成度的兜底池，用于收敛多功能/长尾器件（如 Specialized_PMIC）

## 参考案例

### 电容器（已完成调整）

调整前 `Non_Polar_Fixed_Capacitor_Base` 有 5 个 L3（MLCC_SMD、Leaded_Ceramic、PET_Film、PP_Film、PPS_Film），问题：安装方式和薄膜材质不应做 L3，且互斥性差。

调整后：

```
Non_Polar_Fixed_Capacitor_Base
  ├── Ceramic_Capacitor     ← 介质结构不同，字段不同
  └── Film_Capacitor        ← 物理结构不同，字段不同
      字段：film_dielectric_material = PET/PP/PPS/PTFE
            mounting_style = SMD/Radial/Axial
```

### DSP（已完成调整）

调整前 3 个 L3（Fixed_Point_DSP、Floating_Point_DSP、Multicore_DSP），问题：计算精度和核心数是参数特征，不是稳定的结构差异，且字段集高度重叠。

调整后：

```
DSP_Base
  ├── General_Programmable_DSP  ← 通用可编程DSP，字段含运算精度/核心数
  └── Audio_DSP                 ← 功能/接口体系明显不同，字段集差异显著
```
